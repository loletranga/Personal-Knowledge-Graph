# 知识库规范详表（schema）

供 Agent 在起草元数据、生成输出时查阅。用户日常写作只需 SKILL.md 里提到的"规范速览"。

## 1. frontmatter 字段规范

```yaml
---
date: 2026-09-16                # 结论产生日期（非 reference 必填），支持 2026/9/3 等格式，脚本会归一化
domain: 高校改革                 # 单值或列表；领域建议：高校改革 | 高校管理 | AI产品研发 | 其他自定义
project: 民办大学业务链3          # 可选，对应子目录/项目名
status: active                  # active(现行结论) | superseded(已被取代) | reference(参考资料，缺省值)
supersedes:                     # 我取代了谁（可多个）→ 演进边
  - "[[民办本科院校治理破局方案v-b]]"
related:                        # 语义相关（可多个），"[[文件]]: 为什么相关"
  - "[[education-ai-analysis]]: 同为 AI+教学分析，偏宏观视角"
conclusion: 治理改革走业务链重构先行，而非组织架构调整先行   # 一句话结论（非 reference 必填）
tags: [决策]
---
```

### 字段判定规则（Agent 起草时遵循）

| 判断 | 规则 |
|---|---|
| date 用哪个 | 文档里**结论形成**的日期，不是文件修改时间；正文首部有日期用正文的，没有才看文件时间并在交付时说明 |
| status 怎么定 | 文档提出了主张/方案/结论 → active 或 superseded；纯资料（政策原文、工具清单、数据、模板）→ reference |
| active vs superseded | 后写的文档在内容上取代/修正了旧文档的结论 → 新的 active、旧的 superseded，并用 supersedes 双向成链 |
| conclusion 怎么写 | 只写"这篇最终主张什么/拍板了什么"，一句话，主谓完整；写不出就降级 reference，禁止编造 |
| related 怎么写 | 必须带说明文字；只给文件名等于让回忆时的人再猜一遍 |

### 起草禁区

- 不改正文，只在文件头插入/修补 frontmatter
- 不确定日期时用文件创建时间并在交付说明中标注，不虚构精确日期
- 涉密/敏感判断不做：是否 reference 由内容性质决定，与敏感度无关

## 2. 三类边的语义（不要混用）

| 边 | 写在哪 | 含义 | 用途 |
|---|---|---|---|
| supersedes | frontmatter | A 推翻/取代了 B 的结论 | 演进链：回忆时判断哪条结论现行有效 |
| related | frontmatter | A 与 B 相关但不取代 | 决策时该一起看的文档 |
| `[[双链]]` | 正文 | A 提到过 B | 引用溯源 |

区分口诀：**"决策时一起看"是 related，"我推翻了它"是 supersedes，"我提到过它"是双链。**

## 3. 链接约定

- `[[文件名]]` 或 `[[子目录/文件名]]`，带不带 `.md` 均可；含空格原样写
- 同名文件用路径消歧；`[[名|别名]]` 的别名部分被忽略
- 解析顺序：精确路径 → 全库唯一文件名 → 断链（进 report.md，人工处理）

## 4. 生成物格式

`gen_kb_graph.py` 每次全量重建 `<根>/graph/` 下四个文件：

### INDEX.md — 决策登记簿（回忆时首读）

```markdown
# 决策登记簿
| 日期 | 文档 | 一句话结论 | 状态 | 现行版 |
|---|---|---|---|---|
| 2026-09-16 | [[a/方案v-a|方案总体v-a]] | 业务链重构先行 | active | — |
| 2026-09-10 | [[a/方案v-old|初版方案]] | 组织架构调整先行 | superseded | [[a/方案v-a|方案总体v-a]] |
```

只收录 active/superseded；superseded 自动挂"现行版"链头。

### GRAPH.md — 按领域分组的邻接表

每篇文档：日期、`[[链接|标题]]`、状态（非 active 标注）、结论；下列 取代/被取代/相关/引用 四组出边。全库一章读完即掌握全图。

### kb-graph.json — 机器可读

```json
{"generated_at": "...", "nodes": [{"id": "...", "title": "...", "date": "...", "status": "...",
  "domain": ["..."], "project": "...", "conclusion": "...", "brief": "无结论时的正文首行摘要",
  "tags": [], "has_frontmatter": true}],
 "edges": [{"from": "...", "to": "...", "type": "supersedes|related|references", "note": "..."}]}
```

Agent 做多跳分析、统计、批量改写时优先读它。

### report.md — 健康报告（迭代模式的任务清单）

七个部分：总览计数 / 缺 date / 缺 conclusion / 断链 / superseded 但无人取代（多半是新文档漏写 supersedes）/ 演进链成环 / 缺 frontmatter 清单。**每次迭代从这份清单开工。**

### kb-graph.html — 单文件可视化页面

零外部依赖（无 CDN、离线可开），双击即用浏览器打开。瑞士国际主义/档案风格：纸感点阵底色、硬边框与硬投影、等宽字排印、红色点缀。包含：

- **图谱视图**：力导向布局。每个节点是一张**档案卡片**——上排等宽小字（日期 + 领域色点，active 日期为红色），中间加粗标题，下方红竖线引用式的一句话含义（conclusion，缺失时取正文首行）；superseded 卡片虚线米色化并标注"已取代"，卡片随关联增多而视觉加重。边分三型：红色箭头实线=取代、蓝色实线=相关、灰色虚线=引用。支持滚轮缩放、拖拽平移/调位、单击弹出档案详情面板（NODE FILE：元数据+结论高亮块+关系跳转）、双击打开源 md 文件；缩放过远时自动隐藏卡片摘要行
- **清单视图**：决策登记簿（含"现行版"列）+ 全部文档两张表，与 INDEX.md 同源；无结论文档在表中显示灰色简要含义
- **工具栏**：标题/结论/含义/文件名搜索、领域与状态筛选（图谱和清单联动）

页面头部为档案标记（红方块 + KNOWLEDGE ATLAS + 统计条 + 生成时间/根目录），是生成物，更新知识库后自动刷新。

## 5. 回忆模式输出格式

```markdown
## 相关思路（n 篇）
- 2026-09-03 | reference | 无人机专业证书调研与培养方案分析 → [[无人机应用技术专业证书调研与培养方案分析]]
- 2025-07-22 | active    | 实训设备采购走招标确认流程 → [[机械臂实训设备采购需求确认]]

## 演进链
- 治理改革路径：初版"组织架构先行"(09-10) 被总案"业务链重构先行"(09-16) 取代，现行后者

## 对当前问题的参考点
- 证书合作模式已有结论（1+X 路径），可直接沿用
- 实训设备采购的确认流程可直接复用
- "是否扩招"未发现历史决策记录——本次属全新决策
```

最后一条"无先例声明"在查不到历史决策时必须输出。

## 6. 排除与忽略

- 默认忽略：隐藏目录（`.` 开头）、`.venv` / `venv` / `node_modules` / `__pycache__` / `.git`、输出目录自身
- 额外排除：`<根>/.kbignore`，每行一个通配（`books`、`old/*`、`*_draft.md`），`#` 开头为注释
- 只扫 `.md`；HTML/PDF/图片不入图（需要时先转 md）

## 7. 升级触发条件

| 信号 | 动作 |
|---|---|
| 文档 >500 篇，GRAPH.md 一次读不完 | 迁 LightRAG（图谱+向量混合检索），frontmatter/双链即迁移语料 |
| 需要时间感知的多跳推理且超出上下文 | Neo4j + Graphiti |
| 知识库要给团队/学校用 | 多租户平台（Dify/MaxKB 等），另行走自部署方案 |

到阈值之前不引入数据库和外部服务——文件式图谱的维护成本趋近于零，这是它能长期存活的原因。
